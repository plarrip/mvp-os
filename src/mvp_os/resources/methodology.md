# MVP-OS Methodology

MVP-OS is the product-learning layer for taking an idea toward a validated MVP.

## Lifecycle
G0 Intake → G1 Problem/User → G2 Hypotheses → G3 Validation Strategy →
G4 Product Definition → G5 SDD/Technical Definition → G6 MVP Readiness →
G7 MVP Validation → G8 Learning/Decision.

The lifecycle is non-linear: evidence can move a project backward, forward, pause it, or stop it.

## Evidence model
OBSERVATION → ASSUMPTION → HYPOTHESIS → EXPERIMENT → EVIDENCE → LEARNING → DECISION.

## Lean doctrine
- Identify important assumptions before building.
- Prefer the cheapest credible experiment.
- Manual, fake, prototype, and concierge tests are valid.
- Do not optimize unvalidated assumptions.
- Do not expand MVP scope without explicit value or learning justification.
- Keep conversations bounded and action-oriented.
- If evidence is insufficient: `INSUFFICIENT EVIDENCE`, state what is missing, and stop.

## Gate principle
A gate is passed because decision-relevant information/evidence is sufficient, not because documentation is complete.

## SDD boundary
MVP-OS owns product discovery, hypotheses, experiments, evidence, learning, decisions, and MVP scope.
An SDD provider owns technical specification and implementation workflow.
